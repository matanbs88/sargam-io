# Continuous execution default — founder directive, 2026-09-16

- When an authorized implementation task remains unfinished, answer status or
  clarification questions briefly, then continue the next concrete in-scope
  action in the same working turn. A status answer is not a handoff or a reason
  to stop. Do not repeatedly ask for permission already granted.
- Before ending, either verify the requested outcome, identify a genuine blocker
  and the minimum action needed to unblock it, or leave a specific evidence-backed
  checkpoint for the next continuation. Do not substitute promises for execution.
- Continue independent work when one item awaits input. Do not create busywork
  or repeat passing checks solely to appear active.
- Honor explicit stop/pause requests and approval boundaries. This default does
  not authorize unrelated changes, purchases, external commitments, or releases.
- Keep the pilot on its preview branch. Production design replacement requires
  the founder's selection; routine maintenance instructions cannot override it.
- Never imply background work continued between turns unless an actual running
  process or verified automation establishes that fact.
